# Мониторинг книг Ozon с управлением через Telegram

Сервис проверяет все включённые серии, книги и товары каждые **30 минут по часам: :00 и :30**. Добавление цели и перезапуск не сдвигают график. После запуска сервис ждёт ближайшей границы получаса; для немедленного обхода используйте `/check` или `--once`. Команды бота обрабатываются отдельно от браузера. В Telegram приходят уведомления о подходящих ценах; обычный отчёт отправляется только при наличии подходящих предложений. Ежедневно в **12:00** приходит обязательный отчёт о состоянии, даже если ничего не найдено или `/reports off`. Время определяется `TZ`, по умолчанию `Asia/Novosibirsk`.

Первоначальная цель — Стивен Кинг, серия **«Король на все времена»**, твёрдый переплёт, цена **с Ozon Картой строго ниже 550 ₽**. Используется предоставленная страница с фильтром и сортировкой:

https://www.ozon.ru/series/korol-na-vse-vremena-21102932/category/knigi-16500/?covertype=537&sorting=price

Порог, другие серии, отдельные книги и исключения управляются через Telegram и хранятся в `data/state.sqlite3`.

## Управление ботом

Отправьте боту `/start` из своего личного аккаунта — появятся кнопки меню. Команды принимает только владелец, заданный `TELEGRAM_ADMIN_ID`, и только в его личном чате. Если уведомления идут в ваш личный чат, ADMIN_ID можно не заполнять: используется положительный TELEGRAM_CHAT_ID. Для группы/канала ADMIN_ID обязателен; команды всё равно отправляются боту в личку, а уведомления идут в настроенный CHAT_ID.

| Команда | Действие |
|---|---|
| `/price ID сумма` | Изменить порог только этой серии/книги/товара, например `/price 2 400` |
| `/defaultprice 550` | Начальный порог новых целей; существующие не меняются |
| `/list` | Все цели, их ID и индивидуальные пороги |
| `/addseries URL \| Точное название серии \| Автор \| Порог` | Добавить серию; автор и порог необязательны |
| `/addbook URL \| Название \| Порог` | Добавить конкретную книгу; название и порог необязательны |
| `/addproduct URL \| Название \| Порог` | Добавить любой товар по полной ссылке `/product/…`; название и порог необязательны |
| `/exclude Название` | Исключить купленную книгу у всех продавцов |
| `/include Название` | Убрать книгу из исключений |
| `/exclusions` | Посмотреть исключения |
| `/pause ID`, `/resume ID` | Приостановить или возобновить цель |
| `/remove ID` | Отключить цель; при необходимости вернуть через `/resume ID` |
| `/check`, `/check ID` | Проверить все включённые цели или одну; во время обхода запрос ставится в очередь |
| `/status` | Текущая работа, расписание, последний отчёт |
| `/reports off`, `/reports on` | Выключить/включить отчёты с найденными предложениями; ежедневный отчёт остаётся |
| `/cancel` | Отменить ввод |

Можно нажать «Порог», «Исключить», «Серия» или «Книга»: бот запросит следующий ввод. Примеры:

```text
/price 1 400
/exclude Зелёная миля
/addbook https://www.ozon.ru/product/zelenaya-milya-king-stiven-250436958/ | Зеленая миля | 450
/addseries https://www.ozon.ru/series/korol-na-vse-vremena-21102932/category/knigi-16500/ | Король на все времена | Стивен Кинг
```

В `/addseries` также можно передать ссылку поиска `/search/?text=…` или `/category/knigi-16500/?text=…`. Например:

```text
/addseries https://www.ozon.ru/category/knigi-16500/?text=лавкрафт+хроники+некрономикона | Хроники Некрономикона
```

Название после `|` обязательно и должно совпадать с полем «Серия» в характеристиках книги. Результаты поиска из других серий отбрасываются, отсутствие подтверждения серии считается ошибкой чтения. Поисковый запрос и дополнительные фильтры сохраняются; твёрдый переплёт и сортировка по цене устанавливаются автоматически, номер страницы сбрасывается.

Для серии укажите **точное имя из характеристики «Серия»**. Для серий автоматически выбираются твёрдый переплёт (`covertype=537`) и сортировка по цене (`sorting=price`). Для отдельной книги отслеживается именно выбранная карточка, независимо от серии/автора и её переплёта; используйте полную ссылку `/product/…`, не короткую `/t/…`.

Каждая серия, отдельная книга и товар имеют собственный порог. `/addproduct` принимает полную ссылку на конкретную карточку; автор, серия и переплёт для товара не проверяются. Цена остаётся строго ценой с Ozon Картой, обычная цена не подставляется. Книжные исключения на товары не распространяются. При обновлении базы прежний общий порог и ревизия копируются во все существующие цели; история уведомлений сохраняется. У новых целей начальный порог берётся из `/defaultprice`, если явно не задан при добавлении. Повторное добавление существующего URL без цены сохраняет индивидуальный порог. Старый формат `/price 400` больше ничего не меняет: бот подсказывает формат с ID. Чтобы указать цену серии без автора: `/addseries URL | Серия | | 800`.

### Когда начинается новая проверка

| Действие | Новый парсинг |
|---|---|
| Изменение `/price ID сумма` | Применяется при следующем плановом обходе; если цена не менялась, ничего не ставится в очередь |
| Та же сумма, неверная команда или изменение цены цели на паузе | Не запускается |
| `/defaultprice сумма` | Не запускается; влияет только на будущие цели |
| Новая серия/книга/товар, изменение серии/автора/порога существующего URL | Проверка по ближайшему расписанию :00 или :30 |
| Повторное добавление с прежними условиями, изменение только подписи книги | Не запускается |
| `/resume ID` | Возвращает цель в ближайший плановый обход |
| `/exclude`, `/pause`, `/remove` | Не запускается; правила применяются во время текущего обхода |
| `/include` | Исключение удаляется сразу, свежая проверка — по ближайшему расписанию |
| `/check ID`, `/check` | Одна включённая цель или все включённые цели соответственно |
| Списки/статус/помощь, `/reports`, `/cancel` | Не запускается |

Цена, исключения и отключение цели перечитываются перед обработкой и после загрузки карточки. Уже начатая отправка сообщения может завершиться до применения изменения. Обычные изменения ждут ближайшего общего планового обхода; `/check` и `/check ID` явно запрашивают внеплановую проверку. Запрос во время обхода ждёт его окончания; несколько запросов объединяются. Ручная проверка не сдвигает :00/:30. Одновременных обходов нет. Если обход пересёк следующую границу, пропущенные интервалы не догоняются: следующая плановая проверка начнётся на ближайшей будущей границе. Настройки и очередь сохраняются в SQLite.

Перед обновлением сервиса остановите `monitor` и сделайте копию каталога `data`. После переноса нового кода пересоберите образ и пересоздайте только `monitor`; VPN-контейнер обновлять не требуется. При старом Compose с ошибкой `ContainerConfig` сначала удалите остановленный контейнер `monitor` командой `rm -f monitor` с теми же Compose-файлами. Каталог `data` удалять не нужно.

## Тихие проверки и ежедневный отчёт

«Найдено» означает: товар в наличии, не исключён, соответствует цели и его цена Ozon Карты строго ниже индивидуального порога. Число ссылок в выдаче само по себе не считается находкой. Если предложений нет, обычный отчёт не отправляется; результат и ошибки доступны через `/status` и в логах. Если подходящие предложения остались, отчёт может прийти даже без новых ценовых уведомлений: история уведомлений и число подходящих предложений учитываются отдельно.

Отдельный поток отправляет ежедневный отчёт в 12:00 местного времени независимо от браузерного обхода и `/reports off`. Он показывает текущее состояние и последний **завершённый полный** обход с его временем, количеством находок и ошибками; если проверка в 12:00 ещё идёт, её результат не выдаётся за уже полученный. Дата успешной отправки сохраняется в SQLite. При запуске после 12:00 пропущенный сегодняшний отчёт отправится после старта; после ошибки доставки выполняются повторные попытки. Для доставки сервис и Telegram должны быть доступны. Отдельное предупреждение о подтверждении возраста остаётся включённым.

## Ubuntu: постоянный запуск в Docker

Установите Docker Engine и Compose по [официальной инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/). Dockerfile содержит совместимые Chromium/ChromeDriver из одного Debian-репозитория и виртуальный дисплей Xvfb. Поэтому на сервере не нужен физический монитор и сохраняется видимый режим Chromium, который использовался локально.

Скопируйте проект на сервер, остановив прежний локальный экземпляр бота. Оставьте `.env` и `data/` приватными. Не запускайте одновременно два процесса с одним токеном: Telegram long polling принимает только один получатель.

Если `.env` уже заполнен, сохраните его. Для новой установки:

```bash
cp .env.example .env
```

В `.env` задайте:

```dotenv
TELEGRAM_BOT_TOKEN=токен_из_BotFather
TELEGRAM_CHAT_ID=ваш_chat_id
TELEGRAM_ADMIN_ID=ваш_личный_user_id
TZ=Asia/Novosibirsk
PUID=1000
PGID=1000
```

PUID/PGID должны совпадать с UID/GID серверного пользователя, которому принадлежит папка `data` (`id -u`, `id -g`). По умолчанию оба 1000. Контейнер работает от созданного для этих UID/GID непривилегированного пользователя. Если каталог создаётся от root, назначьте ему соответствующего владельца до запуска. Не переносите папку `.venv` с другого компьютера: зависимости устанавливаются в образ.

```bash
mkdir -p data
# В отдельном SSH-терминале можно следить за журналом:
docker compose up -d --build
docker compose logs -f --tail=100
```

Теперь отправьте боту `/start`, затем `/status` и `/price 1 400`.

```bash
# Остановить сервис:
docker compose down
# Перезапустить после изменения .env:
docker compose up -d --force-recreate
# Обновить код и образ:
docker compose up -d --build
```

Compose использует `restart: unless-stopped`: сервис запускается после перезапуска Docker/сервера, если не был явно остановлен. Проверьте, что Docker включён при загрузке Ubuntu. Папка `./data` примонтирована с хоста: SQLite, цели, настройки, cookies и профиль сохраняются после удаления/пересборки контейнера. Порты наружу не открываются. Журнал ограничен тремя файлами по 10 МБ. Docker запускает Chromium через Xvfb с HEADLESS=false; опция `--no-sandbox` включена только в контейнерной конфигурации.

Для резервной копии остановите контейнер и скопируйте весь `data/` (SQLite с WAL, cookies, профиль). При переносе с текущего компьютера остановите старый сервис перед копированием. Наличие профиля/cookies не гарантирует их принятие с нового серверного IP.

Альтернатива Docker — [deploy/ozon-monitor.service](deploy/ozon-monitor.service): шаблон systemd с Xvfb. Скорректируйте пользователя и пути, установите совместимые Chromium/ChromeDriver и xvfb, создайте `.venv` и установите `requirements.txt`. В `.env` сохраните HEADLESS=false. Одновременно используйте только один способ запуска.

## VPN и сеть

Для работы без включённого домашнего компьютера через OpenVPN-сервер Archer AX53 используйте отдельный контейнер и `compose.router-vpn.yaml`: [пошаговая инструкция](deploy/ROUTER_VPN.md). Этот вариант заменяет SSH-туннель и `compose.home-proxy.yaml`.

### Домашний узел на Arch Linux

Подготовлены `deploy/ozon-home-tunnel.service` (запускается дома) и `compose.home-proxy.yaml` (на Ubuntu-сервере). Обратный SOCKS-туннель создаётся исходящим SSH-подключением из дома, открывать порт на роутере не нужно. Домашний компьютер должен оставаться включённым. Если его трафик идёт через VPN, Ozon увидит выходной IP этого VPN, а не обязательно домашний IP.

1. На Arch установите OpenSSH (`sudo pacman -S openssh`). Служба настроена на ваш сервер `root@185.236.20.26`.

2. Проверьте `ssh root@185.236.20.26`. Для фоновой службы нужен вход по ключу без интерактивного запроса. Если ключа ещё нет, создайте отдельный `ssh-keygen -t ed25519 -f ~/.ssh/ozon_home_tunnel`, установите публичный ключ командой `ssh-copy-id -i ~/.ssh/ozon_home_tunnel.pub root@185.236.20.26` и добавьте для `Host 185.236.20.26` параметр `IdentityFile ~/.ssh/ozon_home_tunnel` в `~/.ssh/config`. При защищённом паролем ключе ssh-agent должен быть доступен пользовательской службе systemd. Приватный ключ остаётся дома. Проверьте неинтерактивный вход: `ssh -o BatchMode=yes root@185.236.20.26 true`. Затем проверьте туннель в терминале дома:

   ```bash
   ssh -NT -o BatchMode=yes -o ExitOnForwardFailure=yes -R 127.0.0.1:1080 root@185.236.20.26
   ```

   Согласно [документации OpenSSH](https://man.openbsd.org/ssh), `-R` без адреса назначения создаёт SOCKS-прокси на сервере с выходом через SSH-клиент дома. Порт 1080 слушает только loopback сервера. SSH-сервер должен разрешать remote TCP forwarding; при отказе проверьте его конфигурацию, не открывайте SOCKS-порт в интернет.

3. После успешной проверки остановите ручной туннель (Ctrl+C) и установите пользовательскую службу **на Arch**:

   ```bash
   mkdir -p ~/.config/systemd/user
   cp deploy/ozon-home-tunnel.service ~/.config/systemd/user/
   systemctl --user daemon-reload
   systemctl --user enable --now ozon-home-tunnel.service
   journalctl --user -u ozon-home-tunnel.service -n 30
   ```

   Для работы после выхода пользователя включите linger: `sudo loginctl enable-linger "$USER"`. Убедитесь, что ключ доступен службе и компьютер не засыпает.

4. На Ubuntu при обычном запуске Python установите в `.env` `OZON_PROXY_URL=socks5h://127.0.0.1:1080`. Для Docker используйте:

   ```bash
   docker compose -f compose.yaml -f compose.home-proxy.yaml up -d --build
   ```

   Дополнение включает сеть хоста Linux, чтобы контейнер видел SSH-прокси на loopback. Это уменьшает сетевую изоляцию контейнера. Все последующие команды Compose для этой установки выполняйте с обоими `-f`. Если туннель недоступен, Ozon-запросы завершатся ошибкой; переключения напрямую на серверный IP нет. Telegram не использует этот прокси.

Нидерландский сервер сам по себе не доказывает блокировку: проверяйте доступ из браузера сервиса с тем же исходящим IP. Если этот IP не принимается Ozon, нужен другой доступный исходящий маршрут, например собственный российский узел через `OZON_PROXY_URL`. Российский IP также не гарантирует доступ. VPN, через который устройства выходят в интернет через сервер в Нидерландах, не даёт серверу российский исходящий IP.

Парсер не меняет настройки VPN, таблицы маршрутизации и firewall сервера. Он использует доступный исходящий маршрут. VPN для трафика ваших устройств и исходящий маршрут серверного приложения могут различаться — это зависит от конфигурации VPN. Если весь исходящий трафик сервера идёт через VPN, запросы приложения также могут выходить с VPN-IP.

Работа бота и доступность Ozon независимы. Если Ozon блокирует серверный/VPN-IP, сервис отправляет отчёт об ошибке, а не сообщение об отсутствии дешёвых книг. Само наличие VPN не гарантирует доступ к площадке. Регион доставки и аккаунт влияют на цены; при переносе используйте нужную сессию или проверьте регион отдельно.

При необходимости можно явно направить трафик Ozon через уже доступный вам HTTP/SOCKS5-прокси:

```dotenv
OZON_PROXY_URL=socks5://proxy-host:1080
# Для Telegram необязательный отдельный HTTP/HTTPS-прокси:
TELEGRAM_PROXY_URL=http://proxy-host:3128
```

OZON_PROXY_URL применяется и к Chromium, и к curl_cffi. Для Telegram поддерживаются HTTP/HTTPS-прокси. В этой версии URL прокси не должен содержать логин/пароль, путь или параметры. Пустые значения используют обычный маршрут. Прокси не создаётся и не покупается сервисом; поддержка маршрутизации через него не гарантирует принятие IP площадкой. `127.0.0.1` внутри Docker — сам контейнер, не хост: используйте адрес, доступный из контейнера.

## Локальная проверка

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py --check
.venv/bin/python main.py --once
.venv/bin/python main.py
```

`--check` проверяет Telegram без отправки сообщений. `--once` выполняет один обход всех сохранённых целей и отправляет уведомления/отчёт согласно настройкам. Обычный запуск запускает и мониторинг, и управление ботом. `--login` открывает браузер для ручного выбора региона в графической сессии.

Для книги с подтверждением возраста остановите работающий сервис и откройте её в том же профиле:

```bash
.venv/bin/python main.py --login 'https://www.ozon.ru/product/URL-КНИГИ/'
```

В окне сайта войдите при необходимости, укажите свои данные для подтверждения возраста и только после закрытия формы нажмите Enter в терминале. Профиль хранится в `DATA_DIR/selenium-browser`, cookies — в `DATA_DIR/ozon_cookies.json`. Не удаляйте каталог данных; в Docker он должен оставаться на постоянном томе. Используйте тот же DATA_DIR и сетевой маршрут при настройке и мониторинге. Сервис не вводит дату рождения автоматически и не хранит её в своей конфигурации. Срок действия подтверждения определяет Ozon: сохранение профиля не гарантирует, что сайт никогда не попросит его снова. На сервере без рабочего стола нужен удалённый графический сеанс; обычный `docker compose up` с виртуальным дисплеем не показывает браузер пользователю.

При распознанном запросе ввода даты рождения или подтверждения возраста мониторинг немедленно отправляет отдельное Telegram-предупреждение со ссылкой даже при `/reports off`. Текущая цель прерывается, остальные проверяются; бот остаётся доступным. Новая попытка выполняется по расписанию или `/check`. Это распознавание текста известных форм, а не гарантия обнаружения любой будущей версии интерфейса Ozon.

Диагностика конкретной книги:

```bash
.venv/bin/python main.py --inspect https://www.ozon.ru/product/zelenaya-milya-king-stiven-250436958/
```

Она сохраняет очищенный ценовой блок и раскрытое окно банков в `data/diagnostics/`, без cookies и токена. Диагностика сама не отправляет уведомления и не меняет историю.

## Хранение и уведомления

Первый запуск новой версии переносит существующую историю из таблицы `offers` в таблицу уведомлений по целям. Первоначальная серия берётся из OZON_SEARCH_URL. Файл `excluded_books.txt` импортируется **однократно**. После этого исключения и цели меняются через Telegram, а не редактированием файла/.env. Повторный запуск не возвращает исключение, удалённое командой `/include`.

Уведомление приходит при первом обнаружении подходящей цены, дальнейшем снижении или возвращении под порог после подтверждённой недоступности/высокой цены. Настройка `/price ID сумма` меняет ревизию только выбранной цели: подходящая книга может получить одно новое уведомление после смены порога даже при прежней цене. У других целей ревизия и история не меняются. Та же сумма не меняет ревизию. Возврат из исключений проверяет свежие цены с обычной защитой от повторных уведомлений. История разделена по целям; одна карточка в двух целях может дать два уведомления. Ошибки сети/парсинга не сбрасывают историю. После сбоя отправки запись об уведомлении не сохраняется. При аварии сразу после отправки, до записи в SQLite, возможен повтор.

Исключения сравниваются по полному названию без авторского суффикса Ozon, с нормализацией регистра, пунктуации и ё/е. «Оно» не исключает сборник «Оно. Ловец снов». Для него добавьте полное название отдельно.

Для отсортированной серии чтение карточек останавливается при первой подтверждённой цене Ozon Банка **выше** текущего порога. Равенство не вызывает остановку, но не подходит для уведомления. Дорогая книга останавливает только свою серию; остальные цели продолжают проверяться. Ссылки выдачи собираются заранее. Ошибка или неизвестная цена не считаются превышением порога. Следующий обход начинается заново. Если обход пересёк одну или несколько получасовых границ, следующая плановая проверка начинается на ближайшей будущей границе; одновременных обходов и очереди пропущенных интервалов нет.

Если цена подписана «С банками», сервис раскрывает список и проверяет Ozon Банк. Отдельная цена Ozon имеет приоритет. Общая банковская цена допускается только при подтверждённом включении Ozon в открытый список банков без индивидуальных цен. Обычная цена не подставляется вместо цены Ozon Карты.

## Проверки и ограничения

```bash
.venv/bin/python -m unittest discover -s tests -q
docker compose config --quiet
```

Тесты покрывают команды и запрет чужого доступа, хранение/миграцию/конкурентные обращения к SQLite, изменение правил во время обхода, отдельную обработку серий/книг и повтор после неудачной доставки. Сетевые вызовы в этих тестах подменены. DOM-тесты требуют запуска Chromium и включаются отдельно через RUN_BROWSER_TESTS=1.

В среде разработки нет доступа к Docker daemon и запуску Chromium. Поэтому Compose проверен статически, но сборка образа и живой вход с IP вашего сервера **не подтверждены**. На сервере проверьте журнал первой проверки и `/status`. Изменения разметки/защиты Ozon могут потребовать обновления парсера. Неофициальный JSON endpoint не гарантирован: при отказе используется Selenium HTML-режим. Автоматическое решение CAPTCHA не реализовано.
